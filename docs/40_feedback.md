# 건의·버그 접수

- 카테고리: `FEEDBACK`
- 근거: 이 창구의 접수 방침 (2026-09-17 초안 — 운영자 확인 전)
- 섹션 머리의 `[F-01]` 같은 표지를 답변에 인용한다

## [F-01] 접수 대상

- 기능 건의: 없는 기능을 요청 (예: 새 자막 형식 지원, 새 발주처 프로파일)
- 버그 제보: 프로그램이 오류를 내거나, 설명과 다르게 동작
- 검사 오탐 제보: 규정상 맞는 자막을 위반으로 잡거나, 틀린 자막을 놓침
- 문서 오류 제보: 사용법 안내가 실제 동작과 다름

## [F-02] 접수 처리 — 기록만 한다

- 접수 도구가 내용을 **로컬 파일에 기록**하고 접수번호를 돌려준다
- 외부(GitHub 이슈 등)에 자동으로 올리지 않는다. 운영자가 기록을 보고 처리한다
- **약속하지 않는 것**
  - 반영 여부
  - 반영 시점·버전
  - 담당자 회신 일정
- 답변은 "접수했다 + 접수번호 + 더 알려 주면 좋은 정보"까지만 한다

## [F-03] 버그 제보에 받아 두면 좋은 정보

- 실행 방식: 화면(exe) / 명령줄
- 실행한 명령이나 누른 메뉴
- 발주처·언어·종류 옵션 (`-p` / `-l` / `-k`)
- 오류 문구 그대로
- 화면 실행이면 [도움말 → 진단] 결과 (`U-03`)
- 정보가 부족해도 접수는 한다. 되묻는 것은 한 번만
- **접수가 먼저다.** 재현 정보를 먼저 묻고 접수를 미루지 않는다. 접수번호를 알려 준 같은 답변에서 필요한 정보를 한 번 묻는다
  - 이유: 답을 기다리는 사이 대화가 끊기면 제보가 기록에 남지 않는다 (2026-09-17 추가)

## [F-04] 받지 않는 것 — 비공개 자료

- **방송 전 영상·대본·미공개 자막 원문을 붙여넣지 않게 안내한다**
  - 유출되면 계약이 깨지는 자료다
  - 이 창구의 답변 생성은 외부 LLM API를 거친다
- 오탐을 재현하려면 문제 자막의 **형태만** 적어 달라고 안내한다(예: "16자짜리 줄에 영문 약어가 섞인 경우")
- 사용자가 이미 붙여넣었으면 기록에 원문을 남기지 않고, 앞으로는 붙여넣지 말라고 안내한다

## [F-05] 문의와 건의가 섞인 경우

- 사용법 질문 + 기능 건의가 함께 오면: 사용법은 `USAGE` 근거로 답하고, 건의는 접수한다
- "이 기능이 있나요?" → 사용법 문서에 없으면 **없다고 단정하지 말고** 문서에서 찾지 못했다고 답한 뒤 건의 접수를 제안한다
