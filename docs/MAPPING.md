# 카테고리 ↔ 근거 문서 매핑표

- 작성: 2026-09-17
- 이 표가 `context.py`(근거 조립)와 `tools.py`(조회 도구)에 그대로 옮겨진다
- 조각 ID는 각 문서 섹션 머리의 `[ID]` 표지다

## 1. 카테고리와 나눈 근거

| 카테고리 | 한 줄 정의 | 처리 방식 |
|---|---|---|
| `USAGE` | 생성기를 **어떻게 쓰는가** — 데스크톱 앱·SE 플러그인의 메뉴·단추, 검사 결과 보기, 저장·결과 파일 | 문서 조회 |
| `QC_EXPLAIN` | 검사가 낸 **특정 위반 항목**의 뜻·근거·고치는 법 | 문서 조회 |
| `STYLE_RULE` | 자막을 **어떻게 써야 하는가** — 넷플릭스 규정 자체 | 문서 조회 |
| `FEEDBACK` | 없는 기능 요청, 버그·오탐 제보 | 기록 |
| `OUT_OF_SCOPE` | 근거 문서로 답할 수 없는 질문 | 넘기기 |

- 나눈 기준: **처리 방식**이 다르고, 조회하는 **근거 문서가 겹치지 않는다**
- 조회 3종을 더 나눈 기준: 질문의 대상
  - 도구의 동작 → `USAGE`
  - 도구가 낸 검사 결과 → `QC_EXPLAIN`
  - 자막 작성 규정 → `STYLE_RULE`

## 2. 카테고리별 근거·도구

| 카테고리 | 기대 도구 | 근거 조각 | 문서 |
|---|---|---|---|
| `USAGE` | `search_usage` | `U-01`~`U-17` | `10_usage.md` |
| `QC_EXPLAIN` | `get_check_info` | `Q-00`, `Q-01`~`Q-33` + 각 항목이 인용한 조항 | `20_qc_checks.md` (+ `30_style_netflix.md` 해당 조항) |
| `STYLE_RULE` | `search_style_rule` | `KO-I.0`~`KO-II.10`, `GR-1`~`GR-13`, `TM-0`~`TM-7`, `NR-*` 19개 | `30_style_netflix.md`, `31_netflix_related.md` |
| `FEEDBACK` | `submit_feedback` | `F-01`~`F-05` | `40_feedback.md` |
| `OUT_OF_SCOPE` (어문 규범) | `refer_to_nikl` | `R-01`~`R-03` | `50_referral_nikl.md` |
| `OUT_OF_SCOPE` (그 밖) | 없음 | `R-04`, `R-05` | `50_referral_nikl.md` |

- 원문 발췌: `KO-`·`GR-`·`TM-`·`NR-` 조각은 로컬에 원문(`sources/raw/`)이 있으면 도구가 해당 절 원문을 `original`로 함께 돌려준다(`originals.py`). 원문이 없으면 요약만 돌려준다
- 항상 넣는 조각(모든 카테고리 공통): `F-04`(비공개 자료 붙여넣기 금지), `R-04`·`R-05`(범위 밖 기준)
  - 모두몰 `ALWAYS`와 같은 역할. 어느 카테고리로 판정돼도 "대본 붙여넣지 마세요"와 "범위 밖이면 넘긴다"는 알아야 한다
- `get_check_info`는 검사 항목 조각, 그 항목이 `근거:`로 인용한 조항 조각, 리포트 읽는 법 `Q-00`을 **함께** 돌려준다
  - 그래서 `QC_EXPLAIN` 문의의 기대 도구는 `get_check_info` 하나다. `search_style_rule`까지 부르면 도구 호출 적절성에서 틀린다

## 3. 경계 판정 규칙

| 경계 | 예시 | 판정 | 이유 |
|---|---|---|---|
| `USAGE` vs `QC_EXPLAIN` | "리포트의 `미구현 검사`는 무슨 뜻?" | `USAGE` | 리포트 **형식** 질문. 특정 위반 항목이 아니다 |
| | "SDH 읽기 속도 초과 경고가 떴는데 기준이?" | `QC_EXPLAIN` | 특정 경고 항목 |
| `QC_EXPLAIN` vs `STYLE_RULE` | "줄 끝 마침표 경고가 떴는데 왜?" | `QC_EXPLAIN` | 검사 결과를 들고 왔다 |
| | "줄 끝에 마침표 찍어도 돼요?" | `STYLE_RULE` | 검사 없이 규정만 묻는다 |
| `STYLE_RULE` vs 넘기기(어문) | "말줄임표 점 세 개 써도 돼요?" | `STYLE_RULE` | `KO-I.4`에 조항이 있다 |
| | "'돼요'와 '되요' 중 뭐가 맞아요?" | `OUT_OF_SCOPE` + `refer_to_nikl` | 가이드에 조항 없음. `KO-I.21`이 국립국어원으로 보낸다 |
| `STYLE_RULE` vs 넘기기(발주처) | "디즈니+ SDH 읽기 속도?" | `OUT_OF_SCOPE`, 도구 없음 | 공개 근거 없음(`R-04`) |
| `QC_EXPLAIN` vs 넘기기 | "공식 가이드에 없는 실무 자료 검사 항목의 근거가 뭐예요?" | `OUT_OF_SCOPE`, 도구 없음 | 비공개 실무 자료 항목(`Q-00`) |
| `USAGE` vs `FEEDBACK` | "리포트를 폴더로 한꺼번에 내보내는 기능 있어요? 없으면 만들어 주세요" | `FEEDBACK` + `search_usage` + `submit_feedback` | 있는지 확인 후 접수. 두 도구 모두 필요 |
| `FEEDBACK` vs 넘기기 | "번역 단가 올려 주세요" | `OUT_OF_SCOPE` | 생성기 기능이 아니다 |
| `USAGE` vs `QC_EXPLAIN` (미구현) | "(특정 검사 항목)이 미구현이라고 나오는데 그 항목은 뭘 봐요?" | `QC_EXPLAIN` | **특정 검사 항목**을 들고 왔다. 미구현 여부도 그 항목 조각(`Q-*`)에 적혀 있다. 특정 항목 없이 "미구현 검사라는 표시가 뭐냐"만 `USAGE` (2026-09-17 추가) |
| `QC_EXPLAIN`·`USAGE` vs `FEEDBACK` (불만 표현) | "(검사·기능)이 왜 이렇게 동작해요? 너무 불편해요" | 원래 카테고리 | 짜증·불만 **표현만으로** `FEEDBACK`에 보내지 않는다. `FEEDBACK`은 ① 기능을 만들어·바꿔 달라는 **요청**, ② 오류·멈춤, ③ 문서와 다른 동작, ④ 규정대로 썼는데 잘못 잡힌다(또는 잡혀야 할 게 안 잡힌다)고 **알리기만 하는** 제보. 이유·해야 할 일을 **묻는** 문의는 원래 카테고리 (2026-09-17 추가) |
| `USAGE` vs `FEEDBACK` (증상 + 해결 방법) | "(작업 중) 멈췄는데 처음부터 다시 해야 하나요?" | `USAGE` | 문서로 원인·해결이 설명되는 증상은 사용법 안내가 정답(사용자 결정 2026-09-17). 분류기는 문서를 못 보므로 신호는 **해결 방법을 묻는가**다. 고장·오탐을 **알리거나 고쳐 달라는** 제보, **"원래 이래요?"**처럼 동작이 정상인지 묻는 제보는 `FEEDBACK` |
| `USAGE` vs `OUT_OF_SCOPE` (다른 이름) | "(다른 발주처)용 파일도 이 프로그램으로 검사·교정돼요?" | `USAGE` | 다른 발주처·다른 프로그램 이름이 나와도 **생성기 기능**(`플랫폼` 목록의 발주처 기준, 작업 기준 창에서 새 발주처 기준 만들기 등)을 묻는 것이면 `USAGE`. 그 발주처의 **규정 수치**나 그 프로그램 **자체의 사용법**을 묻는 것만 `OUT_OF_SCOPE` (2026-09-17 추가) |

## 4. 확신 부족 게이트

- 판정 확신도가 기준 미만이면 답하지 않고 되묻거나 넘긴다
- 카테고리 판정(`classify`)과 넘길지 판단(`gate`)은 **다른 노드**다 — 과제 요구
- 기준값은 모두몰 실습 값(0.5)에서 시작하고 fewshot 분할로 조정한다. 평가 분할로 조정하지 않는다

## 5. 사용자에게 보이는 글에는 규칙 번호를 쓰지 않는다 (사용자 결정 2026-09-17)

- 생성기 리포트의 규칙 번호(`C01`·`T05`·`S02`)와 검사 이름(`reading_speed_exceeded`)은 **사용자가 모른다**고 본다
- 질문(평가 데이터·준비된 Q&A)과 답변(창구 답변·준비된 Q&A 답·모범 답안)에 쓰지 않고, 검사 항목은 **내용**으로 말한다
- 근거 문서(`20_qc_checks.md`)에는 조각마다 "리포트 표시" 한 줄로만 남긴다 — 사용자가 리포트 표시를 그대로 붙여 넣었을 때 도구가 찾기 위해서다
- 검증기(`guardrail.py`)가 답변 속 규칙 번호·검사 이름을 "내부 표기 노출"로 잡는다
- 검사 설명 조각 ID도 규칙 번호를 품지 않게 `Q-01`~`Q-33`으로 바꿨다(옛 `Q-C01`·`Q-S02` 등)

## 6. 사용자는 코딩을 모른다 — 명령어를 안내하지 않는다 (사용자 결정 2026-09-17)

- 이 창구를 쓰는 사람은 코딩을 모르는 작업자다. 명령어·명령줄 옵션은 **알 필요도 없고 알아서도 안 된다**
- 사용법 근거(`10_usage.md`)는 **데스크톱 앱**과 **Subtitle Edit 플러그인**의 메뉴·단추·체크 이름만 다룬다
  - 명령줄에만 있는 기능(장르, 북마크 모으기, 정답 대조, 리포트 파일, 끌어다 놓기용 배치 파일 등)은 문서·Q&A·평가 데이터에서 뺐다
  - 그런 기능을 물으면 "찾지 못했다"고 답하고, 원하면 건의로 접수한다(`USAGE` 규칙 그대로)
- 설치·실행 문제는 [도움말 → 진단...]의 `[없음]` 줄을 제보하도록 안내한다. 설치 명령은 전하지 않는다(`U-14`)
- 검증기(`guardrail.py`)가 답변 속 `--옵션`(출처 없는 옵션)과 명령(`python`·`pip`·`winget`·`ollama` 등, "명령어 노출")을 잡는다
